## 1. Model Quality (WP4 – Preference Modeling)

### M-WP4-01 — Preference Prediction Accuracy (Implicit)

| Field | Content |
|---|---|
| **Definition** | Hit-rate@K: fraction of top-K predicted preferences that match user-accepted actuator actions within a session window W. `HR@K = |{accepted ∩ predicted_top_K}| / |accepted|` |
| **Unit** | % (0–100) |
| **Target** | HR@5 ≥ 80% |
| **Measurement Method** | Automated log comparison: predicted preference vector vs. user-accepted/overridden actions in production logs |
| **RQ Addressed** | RQ1 |
| **Measurement Phase** | WP4 (offline eval), WP6 (pilot) |
| **Baseline** | Rule-based controller (scheduled setpoints), collaborative filtering |
| **Primary/Secondary** | **Primary** |
| **Pilot Required?** | Digital Twin sufficient for initial eval; real pilot for validation |

---

### M-WP4-02 — Preference Prediction Accuracy (Explicit)

| Field | Content |
|---|---|
| **Definition** | NDCG@K on user-rated preference surveys: `NDCG = DCG / IDCG`, where `DCG = Σ (relevance_i / log2(i+1))` |
| **Unit** | Score 0–1 |
| **Target** | NDCG@5 ≥ 0.75 |
| **Measurement Method** | Controlled experiment: users rate system suggestions on 5-point Likert scale; automated NDCG computation |
| **RQ Addressed** | RQ1 |
| **Measurement Phase** | WP4, WP6 |
| **Baseline** | Standard homogeneous GNN (non-heterogeneous), matrix factorization |
| **Primary/Secondary** | **Primary** |
| **Pilot Required?** | Requires real users (or realistic synthetic personas for DT phase) |

---

### M-WP4-03 — Preference Drift Adaptation Speed

| Field | Content |
|---|---|
| **Definition** | Number of feedback interactions N required for model to recover to within δ=5% of baseline accuracy after a simulated preference shift (e.g., seasonal change, occupancy change) |
| **Unit** | # interactions |
| **Target** | N ≤ 10 interactions |
| **Measurement Method** | Controlled simulation: inject preference drift event, track HR@5 over subsequent interactions until recovery |
| **RQ Addressed** | RQ1 |
| **Measurement Phase** | WP4 |
| **Baseline** | Batch-retrained GNN (upper bound), no-update model (lower bound) |
| **Primary/Secondary** | **Primary** |
| **Pilot Required?** | Digital Twin sufficient |
| **⚠ Non-trivial** | Defining "preference drift" operationally is complex. **Mitigation:** use controlled A/B preference profiles injected via the Digital Twin user simulator. |

---

### M-WP4-04 — Multi-occupant Conflict Resolution Accuracy

| Field | Content |
|---|---|
| **Definition** | Rate at which the HGNN produces a Pareto-optimal compromise when ≥2 users have conflicting preferences: `CR_acc = |Pareto-optimal outcomes| / |conflict scenarios|` |
| **Unit** | % |
| **Target** | ≥ 70% Pareto-optimal outcomes |
| **Measurement Method** | Simulation with known preference profiles; evaluate output against pre-computed Pareto front |
| **RQ Addressed** | RQ1, RQ0 |
| **Measurement Phase** | WP4, WP6 |
| **Baseline** | Majority-vote rule, priority-based rule |
| **Primary/Secondary** | **Primary** |
| **Pilot Required?** | Digital Twin for automated evaluation; pilot needed for user satisfaction validation |

---

### M-WP4-05 — Confidence Calibration Error

| Field | Content |
|---|---|
| **Definition** | Expected Calibration Error (ECE): `ECE = Σ_b (|B_b|/n) |acc(B_b) − conf(B_b)|`, partitioned into M equal-width confidence bins |
| **Unit** | Score 0–1 (lower is better) |
| **Target** | ECE ≤ 0.05 |
| **Measurement Method** | Automated: collect predicted confidence scores and binary outcome labels; compute ECE over evaluation set |
| **RQ Addressed** | RQ1 |
| **Measurement Phase** | WP4 |
| **Baseline** | Uncalibrated model (raw softmax) |
| **Primary/Secondary** | Secondary |
| **Pilot Required?** | Digital Twin sufficient |

---

### M-WP4-06 — HGNN vs Baseline Improvement

| Field | Content |
|---|---|

## Composite Scores

### CS-1 — System Intelligence Score (SIS)

Captures the core AI contribution across preference modeling and interaction quality.

```
SIS = 0.35 × norm(M-WP4-01: HR@5)
    + 0.25 × norm(M-WP5-01: TCR)
    + 0.20 × norm(M-WP4-04: CR_acc)
    + 0.20 × (1 − norm(M-WP5-03: Hallucination Rate))
```

**Scale:** 0–1 (higher is better). **Primary RQs:** RQ1, RQ2.

---

### CS-2 — Autonomy Quality Index (AQI)

Balances agent autonomy effectiveness against safety/escalation correctness.

```
AQI = 0.30 × norm(M-WP5-07: ABA)
    + 0.30 × (1 − norm(M-WP5-09: MER))
    + 0.20 × (1 − norm(M-WP5-08: FER))
    + 0.20 × norm(M-WP5-05: Esc_Precision)
```

**Scale:** 0–1. **Primary RQs:** RQ3.
> Note: M-WP5-07 (boundary adherence) is a binary safety requirement — AQI = 0 if any violation occurs.

---

### CS-3 — Privacy-Utility Balance Score (PUBS)

Captures the trade-off between privacy guarantees and model utility.

```
PUBS = 0.40 × norm(M-PRI-01: BCR)
     + 0.35 × norm(M-WP4-01: HR@5_with_DP)
     + 0.25 × (1 − norm(M-PRI-02: MIA_acc − 0.5) / 0.5)
```

**Scale:** 0–1. **Primary RQs:** RQ4.

---

### CS-4 — Infrastructure Robustness Index (IRI)

Summarizes platform reliability across performance and resilience.

```
IRI = 0.25 × norm(M-WP3-01: latency vs. threshold)
    + 0.25 × norm(M-SCL-01: latency degradation)
    + 0.25 × norm(M-SCL-04: availability)
    + 0.25 × norm(M-WP3-04: recovery time)
```

**Scale:** 0–1. **Primary RQs:** RQ0.

---

### CS-5 — Human-Centric Value Score (HCVS)

High-level outcome index for the thesis conclusion and stakeholder reporting.

```
HCVS = 0.35 × norm(M-USR-01: comfort score)
      + 0.25 × norm(M-USR-04: explainability)
      + 0.20 × norm(M-USR-02: conflict resolution)
      + 0.20 × norm(M-USR-05: energy efficiency)
```

**Scale:** 0–1. **Primary RQs:** RQ0, RQ1, RQ2.
